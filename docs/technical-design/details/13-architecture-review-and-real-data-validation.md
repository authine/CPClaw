# 架构评审与真实数据验证技术方案

## 执行顺序

1. 架构师 A：全栈静态审查并修复 P0/P1；
2. 架构师 B：独立复审变更和持久化/安全边界，修复遗漏；
3. 测试专家 A：自动化全量测试、前端构建和 API 回归；
4. 测试专家 B：真实 MySQL、云枢元数据和可安全执行的真实查询验证。

## 证据要求

每条结论必须标记为“代码事实、自动化结果、真实环境结果或未验证假设”。真实环境测试记录数据库产品、迁移版本、元数据数量、查询来源和耗时，但不得记录密码、API Key、Cookie、完整业务敏感数据。

## 安全门禁

发现 H2、未迁移 schema、加密密钥缺失、真实凭据不可用或目标操作不可回滚时，停止破坏性测试并报告阻塞；不得为了通过测试修改真实数据或绕过确认机制。
