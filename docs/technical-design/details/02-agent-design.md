# 受治理 Agent 与语义任务设计

> 文档类型：专项技术设计｜状态：统一 Runtime 主链已实现并验证；真实写操作和生产身份治理仍为发布门禁。

## 1. 设计原则

Agent 不是任意工具调用器。它只能在已同步元数据、已注册 Skill、主体权限、计划校验和确认策略共同限定的范围内工作。模型输出是候选理解或表达，不是执行授权。

## 2. 统一任务生命周期

`UNDERSTAND → DISCOVER → PLAN → VALIDATE → EXECUTE → ANALYZE / PROCESS → COMPLETE`

| 阶段 | 输入 | 输出 | 强制约束 |
| --- | --- | --- | --- |
| UNDERSTAND | 用户目标、会话受控上下文 | 目标、缺口、风险类别 | 不暴露思维链，不以词表替代语义 |
| DISCOVER | 已同步元数据、Skill 能力 | 候选对象/字段/操作 | 不生成不存在的编码 |
| PLAN | 候选与目标 | 受约束执行计划 | 只用白名单动作和字段 |
| VALIDATE | 计划、主体、权限、确认状态 | 可执行/澄清/待确认 | 写风险需记录引用、有效期与幂等 |
| EXECUTE | 已验证计划 | 原始受控结果 | Provider 隔离云枢协议 |
| ANALYZE / PROCESS | 数据或操作回执 | 结论、证据、缺口 | 确定性计算事实，模型受限解释 |
| COMPLETE | 全部阶段结果 | `TaskExperienceEnvelope` | 给出明确终态与 `hostAction` |

## 3. 上下文、记忆与多轮

会话消息、结果引用和主体范围记忆作为上下文输入。引用“刚才的记录”必须解析为保存的结果引用（对象、记录 ID、来源任务、行号、过期时间），不能通过全局重新搜索获得。记忆不提升权限，也不替代确认。

## 4. 通用对话边界

一般对话应由受限宿主/模型路由安全完成，不访问云枢数据。路由依据结构化意图和上下文，不应靠固定主题关键词；同名业务对象必须仍可进入元数据发现。模型不可用时使用保守降级并解释限制。

## 5. 结果与可见过程

对用户可见的过程只包含真实执行的业务化阶段、证据和下一步。内部 Prompt、推理、schema/api 编码和原始载荷只保存在受控审计。Web/MCP/CLI 消费同一 `TaskExperienceEnvelope`；Web 的旧 DTO 仅用于渲染适配。

## 6. 当前限制与技术债

默认主链已不使用历史 Agent 编排器；但 `YunshuAgentOrchestrator` 仍作为旧 `/api/agent/preview` 依赖存在，内含关键词规则。它必须移除或改为纯 `TaskGateway` 委派后，才能满足“无遗留场景判断路径”的严格目标。
