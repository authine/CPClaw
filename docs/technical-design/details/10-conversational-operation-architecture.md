# 对话式受控操作架构

> 文档类型：专项技术设计｜状态：只读任务、澄清、确认和审计主链已实现；真实写操作、流程处理、导入和复杂编排为方案/规划。统一 Runtime 权威规范见 `20-universal-yunshu-skill-runtime-spec.md`。

## 1. 目标

把自然语言系统操作约束为可验证的计划，而非让模型直接调用接口。计划必须可重放审计、可失效、可确认，并能在失败时说明未完成原因。

## 2. 操作状态机

```text
received → understanding → discovering → planned
  ├─ clarification_required → continued → planned
  ├─ confirmation_required → confirmed → executing
  └─ executing → completed | failed | cancelled
```

每个状态都由 `SemanticTaskRuntime` 记录为任务/事件，并通过 `TaskExperienceEnvelope` 返回。Host Adapter 不能跳过确认、伪造终态或将失败转成成功。

## 3. 计划约束

- 对象、字段、关系和操作仅来自同步元数据与白名单 API。
- 查询必须记录数据范围、过滤、返回数量和证据；分析使用业务字段优先策略。
- 写风险操作必须绑定主体、租户、安装实例、计划哈希、记录引用、影响范围、有效期、幂等键和一次性确认。
- 多轮引用只能使用已保存的 `query_result_references`，不能以模糊自然语言重新定位记录。
- 未完成真实契约验证的操作能力保持禁用，返回澄清或明确不可用原因。

## 4. 能力准入矩阵

| 能力 | 当前状态 | 进一步准入条件 |
| --- | --- | --- |
| 元数据发现、只读查询、通用分析 | 已实现并验证 | 数据范围、权限和真实环境回归 |
| 结果引用、确认、审计、续接、取消 | 已实现并验证 | 压力和跨网络 E2E 持续验证 |
| 新增/更新/删除 | 方案/规划 | 真实 API、字段校验、权限重验、幂等与补偿 |
| 流程待办查询/处理 | 查询需按真实契约验证；处理为规划 | 节点权限、重复提交、状态回查 |
| 附件填单/导入 | 方案/规划 | 来源追溯、病毒/格式校验、失败补偿 |
| 多应用 DAG/Action | 方案/规划 | 子任务依赖、集中确认、回滚边界 |

## 5. 失败与恢复

网络、权限、元数据失配和模型失败均必须产生可解释终态；只允许对等幂等请求 replay。`continuation` 票据需校验父任务、主体、安装实例、有效期和一次性消费。后台队列化断线恢复尚未落地，当前不得承诺在连接断开后仍会继续执行写操作。
