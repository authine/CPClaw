# 全局体验与智能质量技术方案（2026-08）

## 设计原则

以“当前表单版本、当前会话上下文、当前已验证能力”为权威，不依赖页面瞬时状态、过期测试结果或固定关键词路径。

## P0：配置验证门禁

新增未保存云枢连接验证契约。前端将当前地址、账号和密码（密码可为空时表示使用已保存凭据）提交到专用验证接口；返回结果绑定表单版本。保存接口仅在对应版本验证成功后接受写入。服务端再次执行相同门禁，避免绕过 UI。已保存配置的“复测”调用独立接口，不与编辑态混用。

## 智能执行质量

会话路由输入由近期消息、上一轮目标/回答/反馈和本轮内容组成；模型输出仅能选择已登记 Skill 或通用对话。明确业务信号、元数据、权限与确认仍由服务端裁决。回答生成、路由和规划的延迟、Token、失败原因使用统一审计字段，避免重复模型调用和无意义的执行时间线。

## 验证策略

1. 后端：未保存连接的成功、失败、字段变更失效、绕过保存拒绝；反馈快速切换与刷新；会话和流程边界。
2. 前端：按钮可用性、提示文案、加载/失败恢复、用户消息无反馈入口、设置页表单版本门禁。
3. 真实环境：以已持久化数据库和实际运行后端验证页面请求，区分真实云枢数据、Mock 和不可验证的外部模型结论。

## P1：执行时间线与布局稳定性

`AgentRunTimeline` 接收的 `steps` 是完整事实源。生命周期合并仅允许以完成事件替换对应的运行事件；`compact` 仅影响字段条目上限与垂直间距，不参与步骤数组裁剪。这样流式面板与完成后的审计面板读取同一条完整路径，避免运行中先前节点因 `slice(-2)` 不可见。

桌面端侧栏切换取消 `grid-template-columns` 和固定输入区 `left` 的逐帧过渡。状态切换时主工作区只重排一次，侧栏自身保留独立的低成本透明度/位移动画；因此响应式图表不会在 200ms 内被反复测量、重绘和换行。移动端沿用抽屉式侧栏规则。

### 执行过程回归验证

1. 构造 5 个以上流式步骤，验证第一步、当前步骤、完成态步骤均在 DOM 和可见时间线内；验证同生命周期的运行/完成事件只显示一项。
2. 在含长文本与分析图表的会话中连续切换侧栏，确认内容区和固定输入区只发生一次尺寸切换，不存在逐帧重排。

## P1：受控写操作解析与确认展示

意图枚举显式区分 `create_data`、`update_data`、`delete_data`。规则层先识别明确的新增/修改/删除动词；模型规划仅能在对象、字段、过滤条件和执行步骤上补充信息，不能覆盖已明确的写操作类别。模型契约、测试网关和审计展示同步使用该枚举。

元数据检索保留通用召回排序，但 `bestMatch` 在目标包含业务术语时优先选择名称语义匹配的 `entity`；同名 `data_item`、`relation` 仍作为字段/关联线索交由执行规划器使用。该策略避免把“创建线索”路由到仅含“线索”引用字段的其他表单。

前端以独立 `section[role=alert]` 渲染确认卡片，替换带 `overflow:hidden` 的通用 `el-alert`。卡片从 `AgentResponse` 读取业务化的动作、对象和确认摘要；内部代码仅留在审计数据中。布局采用可换行网格，确认按钮位于卡片内部流中，受消息区底部安全留白保护。

### 确认交互回归验证

1. 服务端：创建线索返回 `create_data`，实体候选为“私海线索”；显式创建动作不被模型计划降级或改写为 `update_data`。
2. 前端：确认卡片在桌面与窄宽度下无 `overflow:hidden`，确认按钮完整可见，且不泄露内部意图代码。

## 管理工作台共享壳层实现（2026-08-24）

`SettingsView` 复用 ChatView 的壳层几何基线：288px 侧栏、56px 顶栏和 14px 正文字号；导航主标题/描述分别固定为 14px/12px，点击区保持至少 60px。正文容器扩展到 1120px，表单控件统一为 44px 高度。

响应式行为采用抽屉而非无入口图标栏：≤900px 展示菜单按钮，侧栏使用独立 transform 动画，遮罩点击和 `Escape` 关闭；主内容不在动画期间逐帧改变列宽，避免布局抖动。连接配置的验证结果继续绑定表单版本，防止过期验证结果被保存。

## Token 用量看板 API（2026-08-24）

新增只读接口 `GET /api/audit/analytics/usage`，支持可选的时间、状态、模型筛选。服务端用 `Asia/Shanghai` 将 `AgentRun` 的真实模型 usage 聚合为 `daily`、`weekly`、`monthly` 与 `models`；返回的 `summary`、时间桶和模型桶均含调用次数、已返回 usage 的次数、输入、输出、缓存和总 Token。缺失 usage 的调用仅计数，不产生估算 Token。调用明细继续使用分页接口 `GET /api/audit/analytics`，保持审计与运营查询边界清晰。

## 元数据同步审计（2026-08-24）

新增 `metadata_sync_logs` 持久化表及只读接口 `GET /api/metadata/sync-logs`。控制器在执行同步前，以独立事务落库 `running` 记录；主同步事务提交后更新为 `succeeded`，出现异常则用独立事务更新为 `failed`。因此同步主事务回滚时，失败日志仍能保留，且不会影响既有元数据。升级迁移会从历史图谱快照回填可用记录；新的独立日志不受图谱快照保留策略影响，错误摘要先脱敏再保存。
