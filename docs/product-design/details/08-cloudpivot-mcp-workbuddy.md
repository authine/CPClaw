# 云枢 MCP 与 OpenClaw 兼容客户端接入能力

## 1. 产品能力

CPClaw 提供一个受治理的“云枢能力连接器”，以 MCP 工具形式向 OpenClaw 兼容客户端暴露已验证的云枢 Skill。客户端负责承载工具调用与终端凭据注入，CPClaw 负责云枢环境复用、工具边界、确认、审计和结果解释；首期不宣称已获得客户端用户或租户身份绑定。

## 2. 首期用户流程

1. 管理员在“系统设置 → 集成与发布 → 云枢 MCP 服务”启用 MCP 服务，系统生成不可变的安装实例标识。
2. OpenClaw 兼容客户端通过 SSE MCP 配置加入 CPClaw，配置只包含服务地址、安装实例标识和终端用户自己的云枢凭据；不再要求填写 CPClaw 安装目录或启动本地 Node 脚本。安装标识只代表一个 MCP 安装，不代表业务用户身份。
3. 云枢访问地址只由 CPClaw 已配置的云枢环境提供，不在 MCP 页面或客户端重复配置。
4. 终端用户在 MCP 客户端本地配置中填写自己的云枢账号、密码。客户端仅在 SSE 会话调用时通过安全请求头传递凭据；CPClaw 不保存这些终端凭据。禁用和调用审计均可追溯。

## 3. 能力矩阵

| 能力 | 首期状态 | 安全规则 |
| --- | --- | --- |
| 智能问数/数据分析 | 已发布 | 使用本地元数据白名单和用户云枢权限 |
| 数据查询卡片 | 已发布 | 只返回脱敏、分页后的业务数据 |
| 流程待办/已办/发起查询 | 已验证后发布 | 仅开放已验证只读契约 |
| 智能填单、流程处理、数据写入 | 受控预览 | 先生成确认计划；云枢写契约未验证时不可执行 |
| 删除等高风险操作 | 受控执行 | 计划哈希、有效期、幂等键和人工确认 |

## 4. 验收规则

- 未配置 CPClaw 云枢环境地址不能发布；终端账号密码不回显、不写入 CPClaw 数据库或普通日志。
- 每个客户端安装实例拥有独立发布状态；终端用户使用自己的 MCP 客户端配置调用，账号权限由云枢校验。
- MCP 服务状态、绑定状态、能力状态、最近测试时间和审计入口均在系统设置展示。
- MCP 客户端未提供可信用户/租户透传时，产品明确显示“按安装实例隔离”，不宣称已完成企业用户级身份联动。

## 5. 语义任务入口与可见过程

MCP 对外的默认业务入口是 `yunshu_handle_request`。终端 AI 只提交自然语言目标、有限的已获用户同意的上下文和展示偏好；它不需要、也不应猜测 `schemaCode` 或流程 `apiCode`。CPClaw 先在最近一次成功同步的本地元数据中定位业务对象和可用能力，再决定查询、追问或生成确认计划。

“展示思考”不指展示模型原始思维链。终端可见的是可核验的任务轨迹：理解目标、匹配到的业务对象、确定的读取范围、已调用的数据来源、结果核验，以及“需要补充信息”或“等待确认”等状态。若 MCP 客户端提供进度令牌，执行中通过标准 MCP `notifications/progress` 实时发送这些摘要；无实时渲染能力时，最终工具结果仍包含完整 `executionTrace`，因此过程不会丢失。

首期高阶入口自动执行本地元数据已匹配的只读查询和流程只读查询；对象不唯一时返回澄清问题；新增、修改、删除和流程处理仍只返回确认计划。MCP 工具调用不能自行证明人工确认，故在获得可信宿主确认契约前不开放外部写入执行。对通用客户端的 `tools/list` 只发布 `yunshu_handle_request`，原有原子接口不对外发布，避免终端 AI 索取或猜测 `schemaCode`、`apiCode` 等内部编码。

## 6. 语义任务助理能力（规划）

云枢 MCP 的定位是“员工的云枢任务助理”，而不是让终端 AI 拼接原子 API。用户以自然语言提出目标，助理结合对话上下文、当前用户权限和最近成功同步的元数据完成理解、追问、计划、执行和回执。内部可采用 ReAct/反思，但对用户只显示可核验的业务过程，不展示原始思维链。

| 用户目标 | 助理行为 | 交付形式 | 写入边界 |
| --- | --- | --- | --- |
| 数据洞察与分析 | 按关系元数据定位主对象及关联对象，读取、聚合并生成洞察 | 指标摘要、图表数据、表格/卡片、结论与数据范围 | 只读 |
| 数据查询与追问 | 返回可引用的结果集；追问沿用任务上下文，可进一步定位记录 | 摘要卡片或表格、记录引用、筛选范围 | 修改/删除先生成确认单 |
| 智能填单 | 从表单元数据抽取字段，逐轮补齐缺失项并输出可读预览 | 字段草稿、校验结果、提交预览 | 需人工确认和真实写契约 |
| 流程处理 | 查询待办、已办、我发起；对待办解释可用动作并准备处理计划 | 流程列表、事项详情、处理预览 | 处理前需人工确认和真实流程契约 |
| Excel 导入 | 接收文件、识别表头、建议字段映射、校验、预览差异 | 映射草稿、错误行、导入预览与任务结果 | 导入前需人工确认和可恢复导入作业 |

跨场景统一遵循：信息不足先追问；风险写入先展示影响范围与可撤销性；确认后以幂等方式执行；执行中提供“理解结论、匹配对象、读取/写入范围、结果”时间线；结果与追问均绑定同一任务上下文。系统状态仅作为任务运行信息展示，不混入业务状态字段。

## 7. 验收与分期

1. 主入口不要求调用方提供 `schemaCode`、`apiCode` 或字段编码，且能处理同一会话内的追问。
2. 元数据唯一命中时，查询与分析使用真实同步对象及关系；不唯一或字段不足时明确追问，绝不猜测。
3. 查询结果可在后续轮次被引用；涉及修改、删除、填单提交、流程处理或导入时，只能进入“等待确认”。
4. MCP 客户端支持进度令牌时可实时收到脱敏进度；不支持时仍能从任务详情取得完整可见轨迹。
5. 导入必须经历上传、字段映射、行级校验、预览、确认、可追踪作业六步，失败记录可下载和重试。
6. 首期先交付持久化任务上下文、只读查询/分析和流程只读；写入与导入仅在云枢真实接口契约、可信身份和确认回调完成验证后发布。
