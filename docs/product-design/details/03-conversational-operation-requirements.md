# 对话式系统操作需求方案（V1）

**文档类型：专项需求规格｜状态：部分已实现，后续阶段仍属规划。** 本文承接产品蓝图，把“自然语言操作云枢系统”拆成可验证、可分期交付的能力，而不是承诺一次覆盖所有场景。

### 当前实施状态

| 范围 | 状态 | 说明 |
| --- | --- | --- |
| 本地元数据约束、查询/分析、确认审计、结果引用、模型受限规划 | 已实现并有自动化/环境证据 | 具体证据见技术与测试文档。 |
| 删除确认执行 | 已实现但仅限已验证路径 | 仍受记录引用、权限和运行态契约约束。 |
| 通用新增/更新、流程、Action、附件填单、跨对象写 DAG | 方案/规划 | 未通过各自准入门禁前不得宣称可用。 |
| 通用对话与任务路由 | 本轮实现范围 | 先识别“直接大模型对话”或“调用业务能力”，不再默认查云枢。 |

## 1. 产品目标

用户使用业务语言描述目标，CPClaw 基于最近一次同步的云枢元数据解析意图、定位应用对象和 API，生成可审计的执行计划；查询类任务直接执行，写入、删除、流程和 Action 类任务先展示影响摘要并取得确认，再执行并反馈结果。

## 2. 范围与核心原则

### 2.1 对话模式与任务模式路由

CPClaw 是面向用户目标的超级智能体；云枢只是当前已注册的一项业务系统 Skill，而不是对话入口的默认处理器。每轮输入先理解用户目标和可用 Skill 的关联，再决定处理模式：

| 模式 | 适用输入 | 处理方式 | 云枢访问 |
| --- | --- | --- | --- |
| 通用对话 | 问候、闲聊、解释、写作和不要求系统数据或操作的讨论 | 直接调用大模型回答 | 不检索元数据、不调用任何 Skill |
| 技能任务 | 问数、业务分析、填单、流程、记录操作及其他需要系统能力的目标 | 先选择已注册 Skill，再由 Skill 的安全边界、元数据、权限和执行计划处理 | 仅在已匹配且准入后访问 |
| 澄清 | 意图、对象或关键条件不足且不能安全判断 | 说明缺失信息并追问 | 不执行写操作，不伪造结果 |

- `HI/hello/你好/在吗` 等高置信问候必须直接调用大模型返回自然语言结果；不得经过 Skill 路由、元数据检索或业务澄清。
- 明确的删除、修改、提交、审批等高风险表达优先进入任务模式；模型不得把它们改判为闲聊，从而绕过确认。
- 通用对话由已配置模型直接作答，允许使用会话上下文，但不得暗中读取云枢数据或把模型常识伪装成业务事实。
- 当前已注册 Skill 为“云枢业务系统”：覆盖已准入的问数、分析、记录级删除和流程目录能力。后续 Skill 通过统一目录登记其名称、适用目标、风险、输入契约与执行器；未注册 Skill 不可被模型虚构或执行。
- 模型不可用时，仅对高置信问候提供明确标识的本地礼貌回复；其余无法判断的输入进入澄清，不假装完成技能任务。
- 用户可见过程要说明“直接对话”或“调用业务能力”的真实路径，不再将所有输入都展示为“核验业务对象、拆解业务任务”。

### 2.3 Agent 智能与治理原则

- Agent 采用受限 ReAct 循环：观察上下文、规划动作、调用白名单工具、校验结果；每轮有步数、超时和停止条件。
- 每个关键动作执行前后都必须经过 Reflection 校验：对象、字段、关系、权限、数据口径、风险和是否继续下游节点；它是可审计的程序检查，不是对用户展示私有思维链。
- 记忆分为会话记忆、执行记忆和可审核的长期记忆；错误猜测、敏感凭据和一次性附件内容不得写入长期记忆。
- 用户可见的是实际发生的理解、元数据匹配、计划、确认、工具结果和校验摘要，不暴露不可验证的私有思维链。
- 当模型配置声明支持思考且用户在本轮开启“深度思考”时，所有模型调用均应请求供应商启用该能力。任务链展示的是脱敏、限长的“模型分析要点”（目标判断、约束和策略依据），不是逐字输出的内部思维链；通用闲聊保持直接回答，仅展示深度思考耗时，不展开业务执行链。
- 会话记忆、长期记忆召回、记忆写入评估、内部模型提示词、`schemaCode`、接口路径及原始请求/响应均属于技术执行细节：不得出现在对话中的“思考与执行过程”，只可保留在受权限保护的审计记录中。
- 对话展示的过程必须随当前问题动态增减：先说明识别出的目标、范围和待补信息，再展示本轮实际拆解出的读取、关联、汇总、确认或校验任务；模型不可用时应明确标注“受限计划”，不能把固定规则路径伪装成 AI 推理。
- “进化”只来自用户纠正、成功执行、失败反馈和人工维护，必须有来源、置信度、版本、过期和回滚标记。

### 2.4 回答质量反馈

- 每条非空助手回答提供点赞和点踩；用户自己的输入不提供质量反馈操作。同一用户在同一回答上仅保留一个当前状态，再次点击当前状态即取消，切换状态覆盖当前状态。
- 后端持久化反馈的设置、切换和取消事件，关联会话、消息和可用的 Agent Run，用于按 Skill、模型、意图和结果质量分析；反馈采集失败不得影响回答展示或后续对话。
- 点踩原因可选；若后续开放原因输入，必须限长、脱敏，且不得把用户输入中的凭据写入日志或训练样本。

### 2.5 上下文连续与回答修订

- 用户的短句追问不默认视为新任务。系统必须结合上一轮用户目标、助手回答、当前反馈和本轮追加要求，判断是继续、补充、深化、纠正还是切换主题。
- “再详细设计一下”“上一版不够完整”“展开说说”等修订表达，在上一轮存在明确主题时直接继承主题并生成改进版，不要求用户重复动作类型或业务对象。
- 上一轮点踩或明确不满意是质量信号，不是新的业务意图；系统应优先补足结构、边界、数据对象、流程、权限、落地步骤和验收标准。
- 只有上一轮主题不存在、上下文互相冲突或继续执行会产生不可逆风险时，才向用户澄清并说明缺失信息。

### 2.1 五类能力

1. **智能问数**：查询单个对象，按字段过滤、分组、排序、统计和分析；仅沿已验证的元数据关系进行跨对象取数。
2. **智能填单**：从自然语言或附件提取字段，匹配表单元数据，校验必填/格式/选项，生成可编辑草稿；确认后创建或更新。
3. **智能流程**：查询当前用户有权限的待办/已办；读取节点、可用动作和意见规则；处理待办前必须确认。
4. **智能操作**：查询列表后支持“第一条”“刚才那个客户”等记录级引用，执行受控的修改、删除或对象 Action。
5. **通用对话操作**：仅对已同步、已验证、已加入白名单且具备权限与风险策略的 API 开放；未知能力必须澄清或拒绝。

### 2.2 强制原则

- 元数据是能力定位和参数校验的权威来源，模型不得生成不存在的 `schemaCode`、字段或 API。
- “确认”必须绑定具体计划、记录/影响范围、用户、会话、元数据版本和有效期；确认不是泛化授权。
- 结果必须区分真实全量、分页样本、降级结果和失败结果；fallback 不得产生业务结论。
- 多对象分析必须有唯一且可验证的关系路径，不能用两个对象总数相除冒充关联分析。
- 权限按执行用户重新校验；管理员同步元数据的权限不等同于业务用户操作权限。

## 3. 用户与主要流程

- **普通用户**：在自身云枢权限范围内查询、填单和处理任务。
- **管理员**：配置连接、同步元数据、维护 API 白名单和风险策略；不代替普通用户执行其业务操作。

统一流程：

```text
自然语言/附件 → 意图与槽位 → 元数据/权限校验 → 执行计划
→ 查询执行或写操作预览 → 用户确认 → 一次性执行 → 审计与解释
```

信息不足时，系统应说明已理解内容、缺失槽位和候选对象；不得直接猜测执行。

对话过程采用业务化呈现口径，而不是固定阶段清单：

```text
理解当前目标与上下文 → 拆解本轮任务（对象、范围、指标、关联、动作）
→ 核验可用数据与权限 → 执行实际任务 → 校验结果 / 请求确认
```

上述步骤按本轮计划动态增减。例如单对象计数不展示关联分析任务，写操作在定位对象后改为“核对影响并等待确认”，多对象分析才展示关联范围与多项数据读取。

## 4. 分阶段交付边界

| 阶段 | 交付范围 | 明确不承诺 |
| --- | --- | --- |
| P0 | 稳定问数/分析；记录级引用模型；列表→精确记录→确认→删除闭环 | 通用新增/更新、流程、附件字段映射 |
| P1 | 白名单对象的自然语言新增/更新；字段级草稿、校验、幂等执行 | 复杂子表、跨对象写入 |
| P2 | 附件提取与字段映射；附件与主记录一致性处理 | 未验证 OCR、表格公式和复杂附件批处理 |
| P3 | 待办/已办查询及单节点审批/处理 | 未验证的浏览器兜底和跨节点编排 |
| P4 | 受控多对象 DAG、业务 Action、更多对象/API 白名单 | “所有系统场景”无限泛化 |

## 5. 验收标准

### G0 统一门禁

真实元数据快照、测试租户、API/权限矩阵、脱敏、审计、确认过期与重放阻断全部通过；后端全量测试和前端构建通过。

### G1 智能问数

单对象计数/明细/聚合、多轮对象承接、已验证关系路径、多页口径和同名对象冲突均通过。每个结论在审计中可追溯到应用、实体、字段、过滤、关系路径、`total/returned` 和元数据版本；业务界面仅展示可理解的数据来源与口径。

### G2 智能填单

每个提取值有用户输入或附件页码/单元格来源；必填、格式、枚举和权限校验可解释；缺项可追问；草稿可编辑；确认后只创建一次；创建失败不得提示成功。

### G3 智能流程

流程中心作为独立业务能力目录，至少包括“我的待办、我的已办、我发起的流程、流程实例、流程工作项、流程节点”。查询类意图需要绑定当前用户权限范围；同意、驳回、转交、加签、撤回和终止等处理意图必须先读取工作项与节点状态，生成影响摘要并等待用户确认。接口契约未验证时只能说明待验证，不得用静态路径或演示数据冒充真实流程结果。

待办/已办按当前用户权限查询；处理前展示实例、节点、动作、意见规则和影响；节点状态变化、过期任务、越权和重复提交均被阻断；成功后可回查新状态。

### G4 智能操作

列表结果生成带 `recordId`、行号、查询运行 ID、版本、权限范围和过期时间的引用；“第一条/刚才那条”只能解析到唯一记录后进入确认；排序变化、引用过期、记录版本变化和批量超阈值必须阻断。

### G5 通用对话操作

每个 API 必须完成契约测试、真实测试租户验证、权限验证、幂等/补偿定义和风险准入；未准入 API 只澄清或拒绝，不伪造成功。

### G6 回答反馈

点赞、点踩、取消和状态切换均可持久化并在重开会话后恢复；同类型重复提交不重复写事件；反馈事件可关联消息，且点踩原因按脱敏规则保存。

## 6. 依赖、非目标与待决事项

- 需要确认 CloudPivot 创建、更新、待办/已办、审批、Action 的真实 API 契约与权限语义。
- 需要确定 CPClaw 的用户/组织/执行主体模型，支撑“我的”、权限重验和审计归属。
- 本 V1 不承诺覆盖所有云枢页面、任意浏览器操作、无权限数据、未同步对象或无法验证的接口。
- 任何代码实现必须在本方案和对应技术方案评审通过后启动，并为每阶段补充独立验收记录。
