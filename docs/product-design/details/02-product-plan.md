# CPClaw 产品路线图与交付边界

> 文档类型：版本规划｜状态：当前路线图。产品定位、旅程和原则只在 `../00-product-blueprint.md` 维护；规范需求只在 `01-requirements.md` 和专项需求中维护。

## 1. 规划原则

产品以“业务任务”为对象、以“真实数据”为依据、以“确认和审计”为治理边界。每一阶段只扩大已完成契约测试、权限验证和失败补偿的能力白名单，不以“支持所有场景”作为未验证功能的验收口径。

## 2. 角色与产品面

- 普通用户：配置个人云枢账号和模型，通过对话查询、分析和执行自身有权限的业务操作。
- 管理员：配置管理员云枢环境，同步和维护本地元数据、图谱、索引、连接状态、风险策略和日志分析。
- 系统管理工作台：左侧功能菜单、右侧交互内容；个人云枢、管理员云枢、元数据同步、元数据查看、Agent 模型、日志分析和安全控制台统一视觉与 URL 直达。

## 3. 版本节奏

| 阶段 | 交付重点 | 退出条件 |
| --- | --- | --- |
| P0 基础可用 | 对话入口、设置、MySQL/Flyway、模型和云枢连接测试、元数据同步/浏览、确定性问数、业务化执行摘要、确认/审计 | 持久化重启、元数据检索、查询和安全回归通过 |
| P1 受控操作 | 结果集记录引用、白名单对象新增/更新/删除、字段草稿和幂等 | 真实测试租户契约、权限重验、过期/重放测试通过 |
| P2 智能填单 | 附件提取、字段来源、必填/枚举校验、可编辑草稿、附件补偿 | 解析结果可追溯，失败不伪造成功 |
| P3 智能流程 | 待办/已办、节点详情、单节点处理、回查状态 | 节点变更、越权、重复提交均被阻断 |
| P4 复杂编排 | 受控多应用 DAG、业务 Action、更多连接器和组织级记忆 | 每个新增能力独立准入，不扩大为任意网页自动化 |

## 4. 当前实现口径

已实现主线是 P0 的大部分能力；日志分析、模型调用 Token 和向量检索属于“可用但受数据/环境限制”的增强项。P1 以后能力不得在 UI、蓝图或测试报告中写成“已支持”，除非有对应代码、接口契约和测试证据。

## 5. 非目标

本路线图不承诺完整多租户身份中心、任意浏览器操作、未经验证的流程/Action API、无权限数据访问、超大规模 BI 或不受控的模型自定义 HTTP 调用。
