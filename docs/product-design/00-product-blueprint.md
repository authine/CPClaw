# CPClaw 产品蓝图

> 文档类型：产品蓝图｜状态：当前产品方向。能力是否可用以“已实现并验证 / 已实现但有限制 / 方案/规划”为准；历史评审不作为交付承诺。

## 1. 产品定义

CPClaw 是一个可扩展、可治理的多 Skill 企业级对话式智能体与任务平台。用户用自然语言表达目标，平台负责选择已安装的 Skill、组织上下文、生成受约束计划、执行或发起澄清/确认，并返回可核验的结果体验。具体领域的理解机制由对应 Skill 提供；云枢 Skill 在其内部使用同步元数据定位应用、对象、字段和操作能力，但这不是 CPClaw 平台层的统一实现方式。

云枢是首个核心 Skill，不是 CPClaw 的业务本体。云枢 Skill 通过统一 Skill 契约接入，负责云枢元数据理解、运行态查询及经批准的操作；其他 Markdown/MCP Skill 也必须遵循同一注册、权限、生命周期和结果契约。

## 2. 产品目标

1. 在 CPClaw Web 中提供直接、连续、可解释的对话式任务体验。
2. 让 OpenClaw 类宿主通过一个高阶 MCP/CLI 委派入口获得同等云枢事实能力，避免宿主与 CPClaw 反复改写任务。
3. 用元数据、权限、确认、审计和证据完成度约束模型，不把具体业务对象或行业规则固化进框架。
4. 让管理员能够治理 Skill、模板、平台设置记忆和连接配置，让个人用户仅访问其授权范围内的能力。

记忆采用三层产品模型：用户会话记忆、用户自定义设置记忆、平台设置记忆。会话记忆服务于当前对话连续性；用户自定义设置记忆保存个人偏好和长期使用习惯；平台设置记忆保存超级管理员配置的系统级规则与公共知识。

## 3. 用户与产品面

| 用户 | 主要目标 | 权限边界 |
| --- | --- | --- |
| 普通用户 | 对话查询、分析和经批准的业务操作 | 个人云枢身份与授权数据范围 |
| 超级管理员 | 连接配置、元数据同步、Skill/模板发布、平台设置记忆治理、审计查看 | 可管理系统级配置与平台设置记忆 |
| 外部宿主用户 | 在 OpenClaw 等终端调用云枢能力 | 由安装实例、主体、租户和运行时权限共同约束 |

无登录部署阶段使用固定默认主体 `huangj`（黄杰）作为本地运行身份；该模式不能冒充任意外部主体，正式多用户和组织授权属于发布门禁。

## 4. 统一任务体验

所有入口遵循同一生命周期：

`理解目标 → 发现 Skill/元数据 → 生成计划 → 校验权限与风险 → 执行或澄清/确认 → 分析/处理 → 完成`

宿主获得版本化 `TaskExperienceEnvelope`，包含业务化结论、证据、缺口、产物、下一步动作和可见进度。内部记忆、模型思维链、云枢编码、接口地址和凭据不外显。

Web 与 MCP/CLI 共享 `TaskGateway → SkillRegistry → Skill Executor` 执行链；Web 的 `AgentResponse` 仅是旧 UI 的兼容映射，不是第二套业务执行器。

## 5. 核心体验原则

- 目标导向：用户描述结果目标，不要求先掌握应用、模型或接口编码。
- 能力真实：每个 Skill 只能使用其自身已验证的能力边界；云枢 Skill 只能使用已同步且仍有效的实体、字段、关系和操作能力。
- 不确定就澄清：范围、对象、记录、必填项或权限不足时停止猜测。
- 写操作可控：新增、修改、删除、流程处理、导入和不可逆 Action 必须经过计划、权限重验、确认和审计。
- 结果可核验：显示来源范围、口径、完成度和未覆盖部分。
- 宿主一致：CPClaw、OpenClaw、CLI 对同一任务使用相同事实、状态和证据。
- 框架无业务固化：具体场景通过同步元数据或已审核模板插件表达，不能在框架代码中写对象词、字段别名或行业风险判断。

## 6. 产品范围与状态

### 已实现并验证

- Web 对话工作台、会话持久化、流式进度、取消、历史未读状态和双主题 UI 基础。
- MySQL/Flyway 持久化、默认主体、模型与云枢连接配置、元数据同步、应用级图谱和确定性检索。
- 云枢只读查询、通用分析结果、结果引用、内部记忆、确认/审计基础。
- MCP 高阶工具、结构化结果、终态 `hostAction`、任务状态/事件/续接/取消、幂等 replay 和 CLI 转发。
- Web 与 MCP 共享同一 Spring 单例云枢 Skill 执行器。
- 声明式分析模板 Manifest 的校验、草稿、审核、发布和停用管理。

### 已实现但有限制

- 模型驱动规划、向量语义召回、复杂关联分析、长任务进度和真实数据规模优化受环境、数据量、身份映射和模型可用性影响。
- 无登录安全模式只适合单用户本地验证；不能替代 OIDC/JWT 和组织级授权。
- 外部宿主目前以 MCP/CLI 契约联调为主，真实跨网络生产 E2E 尚未完成。

### 方案/规划

- 云枢通用新增/更新、流程待办处理、Action、附件字段映射、导入和多应用写入 DAG。
- 模板版本历史、回滚、签名密钥轮换和生产级插件市场。
- 后台队列化断线恢复、组织级记忆和正式多租户身份中心。

## 7. 产品演进

P0 建立对话、元数据、查询、结果和治理底座；P1 扩展受控记录操作；P2 增加附件填单；P3 增加流程处理；P4 扩展复杂编排、组织授权和生产运维。每一阶段必须以独立契约、权限、审计和测试证据作为准入条件。
